# Civilization VII Mod 开发

把功能实现、用户操作和验证证据一起交付。遵循当前用户范围；“做 Mod”不自动授权操作正在运行的游戏、替换安装版或上传工坊。

## 开始工作

1. 定位仓库并读当前 `AGENTS.md`、目标模块 README、清单和相关验证记录；检查工作区改动，保留其他会话与用户的工作。此用户的仓库通常是 `/Users/sunmer/Documents/civ7-mods`。
2. 查 `catalog.json`、实际 `.modinfo`、测试入口和发行回执。索引、README、源码、安装版、工坊版可能不同；不从一个版本的证据推导另一个版本已通过。
3. 按任务阅读参考资料：
   - 了解现有能力与接入位置：[项目上下文](references/projects.md)。
   - 所有用户可见文案及设置：[国际化](references/localization.md)。
   - 任何交互新增/修改：[输入与手柄](references/input.md)。
   - 回归、实机、录制或交付：[测试与发行](references/testing.md)。
4. 默认在仓库离线完成实现与回归。用户说“还在玩”“先不测试”“不要操作游戏”时，不连接游戏调试端口、不点击、不安装、不重启；仍可读本地源码并运行隔离测试。

## 功能和实现标准

- 明确入口、触发动作、适用对象、合法性、取消行为、持久化范围和关闭后的行为。复用原生组件、动作处理器和合法性检查，不仅修改界面显示来假装游戏效果生效。
- 优先把纯规则/规划、引擎适配、UI 和设置分开。使用当前安装游戏及依赖 Mod 的源码确认 API 签名、事件顺序、界面栈；不凭旧文档或字段名称猜测可用接口。
- 保持内部 Mod ID、存储命名空间及旧配置迁移兼容。共享 `modSettings` 必须读取、合并并只改自己的键；损坏数据不直接覆盖。偏好、会话计时、随存档玩法状态分别建模。
- 设置尽量接入原生“选项 → 附加内容”，保留草稿、确认、取消、恢复本 Mod 默认的语义；不要重设其他 Mod 或全游戏设置。
- 自动化仅在授权的游戏范围执行，尊重本地玩家、时代、回合、暂停、弹窗和引擎规则。等待真实完成事件/状态再继续；超时、取消、失焦、读档、对象消失或关闭界面时停止后续动作。失败恢复只处理本次已改变的对象。
- 大规模规划分段让出输入；用户调整资源期间保持列表位置稳定，排序只在明确点击或重新打开时计算。避免响应式效果反复排序或写设置；不在渲染循环中发送操作。
- 新增用户界面默认覆盖英文与简体中文，并设计鼠标/键盘和手柄的完整操作路径。无对应操作时明确标记不适用，不把未测试称为支持完毕。
- 使用局部、可撤销的挂钩，处理重复注册、组件重建和卸载；只恢复仍由本 Mod 持有的原方法，保留第三方所有权和兼容边界。

## 交付

报告具体改动、运行过的检查、跳过项、已知限制，以及源码/安装/工坊各自状态。实机输入注入、实体手柄反馈、离线模拟是不同证据，不混称。仅按用户授权执行安装或发布，遵守仓库游戏锁、备份与 Rest Guard 流程。
