# 鼠标、键盘与手柄

## 功能标准

对每个新入口写出完整链路：打开 → 导航/选目标 → 确认一次 → 观察实际结果 → 取消/关闭 → 返回正确焦点。只给按钮增加 A 回调不算完整手柄支持。

- 复用原生语义动作（Accept、Cancel、导航、cycle 等）及当前设备状态。以 Xbox A/B/LB/RB 描述时注明布局；不把字母当所有设备的固定按键。
- 鼠标右键、Esc、手柄 B 应先取消当前选中、拖拽或选格，再关闭上一层；不要把 B 强行绑定成鼠标右键的业务动作。正在取消的同一输入不得继续冒泡关闭面板或误执行地图操作。
- 区分 START / UPDATE / HOLD / FINISH，完整按下释放只激活一次。持续摇杆采用初始延迟和节流，松开不补一步；断开、失焦、切换设备、切换视图和卸载时清理运动/按下状态。
- 菜单和世界地图使用不同上下文；Mac 的 HOLD→UPDATE 适配来自已复现的特定兼容缺口，不能全局把所有游戏输入改写。原生已经处理的事件不重复分发。
- 方向导航跳过隐藏/禁用控件，长列表随焦点滚动。重建后保持目标身份而不是旧索引；焦点移入不应触发确认。动画/延迟回调后复核，防止地图确认被单位面板重新抢回（战争操作曾有 150 ms 入场动画抢焦点）。
- 弹窗、暂停、输入锁及 Rest Guard 遮罩优先。延迟打开操作要在执行时再次确认设备、视图、目标存在与可用性；不能从后台抢回焦点。
- 调用已有按钮的语义激活或原版动作入口，避免伪造鼠标坐标替代通用手柄实现。可选 Mod 未装时隐藏缺失入口，不吞掉其他原生操作。
- 分开配置鼠标/手柄仅在产品需要时采用。原生 Confirm 保存，Cancel 放弃草稿，Reset 仅重设本 Mod；旧字段兼容不代表对应手柄功能可用。
- 资源拖放必须保留资源值、所属城市、地图外标识等完整身份。开始拖动已选资源不应再次触发点击的取消/交换语义；嵌套按钮不要抢占放置操作而启动另一项自动化。

## 验证级别

| 级别 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 纯逻辑/事件 fixture | 选择状态、合法性、节流、取消、一次激活、清理 | 游戏路由与实体设备手感 |
| 原生源码 + 独立浏览器 | 实际组件 DOM、焦点、导航、列表重建、字体布局 | 当前游戏中的事件和引擎操作成功 |
| 实际游戏输入路由注入 | 引擎确认后的成员/位置/资源/移动力变化、取消无副作用 | 真实手柄驱动、摇杆精度与持续操作手感 |
| 实体手柄或明确用户反馈 | 指定系统、设备、布局、版本、操作范围内体验 | 未覆盖设备、模式、平台或新版回归 |

报告支持时列明级别和范围。例如“英文已离线覆盖；原生手柄路由已测，实体手柄未测”。不需要等待实体手柄才能交付离线修复，但不得写成已实机验收。
