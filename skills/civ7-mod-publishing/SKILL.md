# Civilization VII Mod publishing

把真实功能写成玩家看得懂的图文，并将审核、提交、待审核、公开发布分开记录。用户当轮指令优先；沿用已经给出的发布授权，不重复索要确认。

## 1. 确定范围与证据

- 默认仓库 `/Users/sunmer/Documents/civ7-mods`。先读其 `AGENTS.md`，再结合 `catalog.json`、`mods/`、`apps/` 和相关会话发现项目；目录比旧目录清单更完整。分合的两个模块按一个项目计算；辅助工具单列。
- 对照版本文件、当前代码、验证记录、发行回执及已有公开页面。README 或代理的最终回复不单独构成“已发布/实机通过”证据。分别记录源码版本、已发布版本、截图版本和验证平台。
- 把每项主张连到本地证据。区分离线验证、游戏内合成输入、实体手柄验证；不把一个平台的结果推广到全部平台，不把部分交互当作完整流程。
- 未发布项目写成开发日志或预告，不加虚构的订阅链接。暂停的空壳工具只写概念稿并明确尚无可用产品。
- 发布前刷新会变化的版本、链接、平台规则和实际编辑器能力。历史经验见 [platforms.md](references/platforms.md)，不是永久规则。

## 2. 写稿与配图

- 中文系列名 **《文明7拯救计划》**；英文 **Civ VII Rescue Project**。主题是具体 Mod，标题说清玩家得到的改善，不承诺“彻底修复”“完美兼容”。
- 宣传稿按玩家得到的核心效果分章：具体痛点 → 最终效果 → 真实游戏截图及简短图注。不要把每个设置项或内部实现都拆成卖点。
- 宣传文案不解释为什么独立开关、为什么可配置等显而易见的设计；配置页可用截图和一句入口说明展示，不另写设计论证。修复过的 bug、反复修改的过程和基本正确性（例如存完档再结束回合）不单列章节，直接描述当前最终效果。除用户明确要求更新日志外，不把研发过程写进宣传正文。
- 区分宣传文章与 Mod 产品主页/说明文档：前者聚焦痛点和收益，后者仍保留使用方法、配置入口、适用范围及影响使用的限制。压缩宣传稿不等于删掉产品说明中的必要信息。
- 模仿作者文风时参考已读样本和 `/Users/sunmer/Documents/civ7-mods/work/mod-editorial/author-style.md`，用具体玩家情境和适量自嘲；不编造作者经历、拒绝代价或测试结果。
- 不解释玩家已有的基础操作，不讲内部合并、文件结构或开发实现。依赖 Mod、单人限制、未完成验证等会影响使用的事实必须保留。
- 英文按社区语气改写，不逐字翻译；首次清楚说明作者身份。Reddit 版聚焦两三项改善和反馈问题，不机械复制长专栏。
- 仅复用已经检查过的真实截图。图片必须与主张、版本对应；旧图标明版本，不能证明新流程。设计封面只能是封面，不能代替效果图。静态图不能证明保存成功、操作速度或完整往返。
- 缺图写进独立拍摄清单，预览显示“待补实机图”；成稿正文不混入代理工作记录。不要生成伪游戏画面，也不要用相似 Mod 的截图冒充。
- 补拍涉及游戏时应用 `civ7-modding` 和仓库规则：完整校验 Saves 备份、排队拿锁、暂停/恢复休息限制；大盘不得自行授锁。未经用户授权不自动给原开发会话发任务。

## 3. 交付可审核稿件

在用户指定位置或 `work/mod-editorial/<日期>-review/` 保存：

1. 每项目中文长稿、英文长稿、英文 Reddit 短稿；可复用已经审核发布的版本。
2. 一页可浏览的图文预览；中文/英文可切换，内部缺图说明与公开正文视觉区分。
3. `review.json`：主张依据、版本、验证边界、每章图片来源/缺口、三个平台状态、已有链接、审批范围。
4. 批量入口和拍摄清单。每个实际项目都在清单里；没有内容的项目说明原因，不静默漏项。

检查图片文件存在、预览能打开、章节与图文对应、没有错误订阅链接、英文无遗漏、公开文案没有绝对本地路径。用户说“明早验收”表示准备完整草稿，不等于授权批量发出。明确文字完成与图文可发布之间的差距。

## 仓库提交范围

- 用户要求 PR 只包含代码改动和已发布文案。草稿、待审核稿、批量验收预览和补拍清单留在忽略的 `work/`，不要提交。
- 已发布文案归档到 `docs/publications/<与 mods 同名的目录>/`，仅收录有成功发布回执的平台版本及实际配图；每份记录发布链接、时间和正文哈希。授权发布或提交成功但待审核不等于公开发布。

## 4. 发布与核验

- “先给我看”只做预览；用户说“发布”后按已审核内容发布。合理的平台适配无需再问；重大内容变化或新受众范围需让用户知道。
- 优先已连接平台工具；能力不足才用浏览器。登录由用户完成，不读取或输出凭据。遵守平台当前要求；不要规避验证码、封禁或强制审核。
- 发布前检查目标账号、板块、标题、正文只有一份、图片数量/顺序和预览。编辑器的 fill 可能追加，必须读回核对；必要时选中全文删除、确认空白再填。
- 异步提交时等结果并查找帖子，不因旧页面还在就重复提交。失败或结果未知先查已发记录。
- 成功后保存永久链接、平台 ID、时间、正文版本/哈希、图片数量、审核状态和证据截图。**已提交待审核不等于公开可见**；作者自己能看到也不一定代表游客可见。
- 批量发布逐条记录，已公开或待审核的同一内容不再新建。修订用编辑已有帖子；不要为了绕过审核重复投递。
- 最终用短中文报告各平台准确状态和链接，剩余缺口明确指出。
