# 你的神图很好，现在是我的了

从已有存档复制开局设置，重新选择领袖、文明和纪念物，再微调或直接开新局。

## Mac 启动器接入（开发中）

现在可由独立 [更好的Mod支持](../civ7-mac-launcher/) 随 Steam 自动启动辅助服务，并在游戏退出时关闭。组合包携带 Node，不需要用户另装运行库。会话令牌通过已有通信桥传入内存，不修改安装目录。完整存档导入仍依赖本机 Cohtml 调试桥，启动器不自动启用该通道；0.4.0-dev 通过注册协议接入游戏“选项 → 增强 Mod”，无需专用启动参数。已实测通过注册服务导入并核对全部 834 项设置；仍不能称为干净环境安装即用。下面旧 `.command` 和手工工具说明仅描述历史路线。

## 单行复制码（0.3.6-dev）

“粘贴配置文字”入口现在同时接受中文种子说明、`C7L1` 阵容码、`C7S1` 常用设置码和新增的 `C7S2` 扩展设置码。无需辅助程序或联网。

- `C7L1` 兼容 [Ghosts Civ7Generator](https://ghost-ng.github.io/Civ7Generator/) 的时代、`H:领袖:文明`、`A:领袖:文明` 格式。当前入口用于单人新建游戏，只接受一个 H；AI 按席位顺序填入。
- `C7S1` 可另外携带地图、尺寸、速度、难度、两个种子以及可选的玩家阵容。例如：

```text
C7S1;MAP={base-standard}maps/pangaea-plus.js;SIZE=HUGE;GAMESEED=1467319409;MAPSEED=1467319429
```

在粘贴窗口中点“生成当前设置码”，现在生成 `C7S2` 单行文本：除基本设置与阵容外，自动收录当前可读取的两格纪念物（含空槽）、团队、玩家难度，以及游戏开放的高级选项。覆盖时代长度/过渡规则、独立势力、灾害、起点/海平面、自定义难度、胜利/危机/传承路线等；第三方 mod 的同类开关、整数、单选和多选项也会自动收录。

导出显示收录数量，提供“查看未收录项”；隐藏、不适用、无法取得稳定编号或不支持类型的项目会列明原因。未编码 DLC/MOD 清单、账号、会话或存档进度，因此不宣称能保证完整复现任意存档。第一页仍只有两个入口按钮。

导入先预览，再按当前游戏的实际可选项填入。时代变化后重新查询领袖/文明，领袖变化后重新查询文明。无法使用的内容明确报出并停止后续填入，不擅自换成随机；之前已经采用的项目会保留。玩家数量超出上限不会悄悄丢弃 AI。`C7L1` 未提供种子时会保留原有种子。

本版 **131 项离线测试通过**，包括复制码往返、原文 7 人阵容、动态选项、纪念物互换/空槽/解锁检查、高级设置全部类型及实际界面脚本接入；没有实机调试或更新安装目录。详见[复制码格式和验证记录](docs/setup-codes.md)。

## 当前优先：粘贴一组配置文字（0.3.4-dev）

2026-10-22 用户将桌面应用留作备用，当前先做不依赖辅助程序的文字输入。新建第一页保留“读取设置文件”和“粘贴配置文字”。支持：

```text
1游戏种子：1467319409 宽广盘古大陆 巨大
1地图种子：1467319429。
```

这段文字识别为游戏种子 `1467319409`、地图种子 `1467319429`、`宽广盘古大陆（经典）`、`巨大`。预览后点击“填入设置”，先调整地图/尺寸，再填写种子，最后检查游戏返回的值。缺失或当前不可用的选项不强行写入，领袖、文明、纪念物等继续在原生新建界面选择。

输入使用游戏原生 `fxs-textbox`，同时支持可读取内容的粘贴事件与引擎原生文字输入；两行被合并成一行时也保留编号和种子配对。一次只接收一组。空输入或粘贴图片只给出文字提示，不再自动调用旧 OCR 工具。

本轮只修改仓库并离线测试，没有更新游戏安装目录、热加载、重启、读取或写入用户存档，也没有实机验证新版 UI。以下 0.3.3 及更早章节保留为历史研发记录。

## 交付标准：只安装 mod 即可使用

用户已澄清：**允许读取存档文件，也允许附带程序、运行库或 OCR 组件；限制的是用户不需要另装软件、另行启动工具、配置环境或额外授权。** “纯 mod”在本项目指这一使用体验，不是“只能用 JavaScript”或“禁止访问文件”。组件可以随 mod 一起交付，但其加载、调用和平台兼容也必须在正常安装后自动工作。

**这个目标尚未完成。** 原有“mod + 手动启动本地工具”的验收结果不满足该标准。目前也未验证游戏能自动启动/加载附带的原生组件，因此不能只把工具拷进 mod 文件夹就称为完成。

此前暂停实机期间只修改仓库源码和运行离线检查。2026-10-22 用户重新授权测试后，已在每次完整备份存档的前提下完成主菜单中的附带工具通信探测，未加载/启动对局，也未更新安装中的 mod。游戏目录中的既有版本不随工作区修改而更新。

`0.3.3-dev` 已在源码中完成：

- 新建第一页直接显示“读取设置文件”和“粘贴图片或文字”，移除中间的来源选择弹窗。
- 读档页只新增“以此设置新建游戏”一个按钮，去掉“保存为游戏设置”和主动“检查 DLC 和 MOD”。原版的配置保存/读取功能不改动。
- 一次只接收一组。支持带编号或不带编号的局部种子分享文字和 Esc 配置截图文字；多组输入要求重新截取，不再展示选择/翻页界面，也不混用不同组的两个种子。
- 纯文字使用游戏内输入区域与粘贴事件解析，不要求本地工具；无法取得事件内容时保留引擎的原生文字粘贴。解析后先核对，确认才填入。
- DLC/MOD 提示只在加载失败且发现具体依赖问题时出现：必需项红色，可选项黄色。使用游戏已提供的内容清单，不再另发辅助工具诊断请求。正常加载不弹检查结果。
- 存档解析核心迁到 `ui/save-reader.js`，不依赖 Node、Buffer、TextDecoder、文件访问或调试接口。原有主机工具复用这一核心。它已能在隔离的 JavaScript 环境解析完整起始配置，**不代表游戏已经能读取所选存档的文件字节**。
- 转换为原生配置和生成逐项核对数据也迁入 `ui/save-configuration.js`。保留两份独立快照：原始开局设置，以及仅调整新局状态/已确认界面 mod 版本后的待加载设置；嵌套数组、64 位数字和原生值也独立保存，避免后续重置或修改污染核对依据。旧主机工具只负责文件读写和哈希，不再维护另一份转换算法。

尚未打通的两项：

1. 游戏内取得普通存档的完整数据，并只恢复起始配置。当前可工作的导入链仍调用原有本地工具；纯 mod 的文件读取入口仍在研究，未切换为未经验证的原生调用。
2. 图片剪贴板及内置 OCR。免费开源引擎和系统 OCR 确实存在，但尚未找到游戏内取得粘贴图片及调用识别引擎的完整通道。当前图片路径仍是既有 macOS 辅助程序；没有以文字导入冒充图片识别。

因此本版不应上传工坊或宣传“装上即用”。`tools/` 中保留既有开发/验证工具，不将其手动启动要求作为最终产品方案。后续同时评估游戏原生接口和随 mod 自动运行的组件，不预先排除文件读取或二进制组件。

## 已有验证

截至 2026-10-22，**94 项离线测试通过**，包括实际界面脚本在模拟游戏边界下的直接入口、单组校验、纯文字无辅助程序路径、依赖失败提示，以及完整二进制解析/转换、未知属性/64 位数值保留、非法 UTF 编码拒绝、不会改变源字节等。新增检查确认即使两个种子相同，当前对局中已确定的随机领袖和变化后的纪念物也不能冒充原始开局设置。

旧的真实存档副本也通过新的纯 JavaScript 解析器复核：51 个游戏属性、16 个地图属性、64 个玩家槽位与先前结果一致，95,222 字节起始配置原样保留。使用的是 `work/` 中已有副本，没有访问正在玩的存档。

新迁移的转换核心生成 169,267 字节原生配置，与迁移前工具的输出逐字节一致。该结论是离线字节一致性，不是新版本实机验证。详见[继续开发记录](docs/validation-portable-conversion-2026-10-22.md)。原生大厅方案的静态核查发现返回菜单和进入新建会重置设置，且大厅可能展示当前状态；因此没有把这条未验证路径接成默认按钮动作。

这轮产品代码没有实机验收。每次实机测试之前必须先完整备份整个 Saves（含 auto、auto/prev、quick），核对路径、大小、SHA-256，再检查真实布局、粘贴支持和原生存档入口。详见[本轮离线记录与 OCR 调查](docs/validation-standalone-offline-2026-10-21.md)和[社区解析器、官方接口与专用 skill 调查](../../docs/research/civ7-save-import-ecosystem-2026-10-21.md)。

2026-10-22 的独立通信探测已有一项进展：游戏原生保存专用配置请求 → 外部监听器读取并写出回复 → 游戏原生配置列表发现回复，最小信号往返成功，消息无需调试连接传递。测试没有加载回复配置，监听器仍由开发环境启动；**尚未找到普通 mod 自动启动附带程序的受支持入口**，不能据此宣称“只安装 mod 即可使用”。当前 Mac 主菜单里的 localhost HTTP/WebSocket 探测也未成功，外部客户端对同一服务的正向对照通过。详见[附带组件与通信实测](../../docs/research/civ7-bundled-helper-2026-10-22.md)。

这次测试前的完整备份覆盖原有 327 个文件、1,373,458,119 字节；测试后所有原始路径、大小及 SHA-256 一致，两个专用测试配置已归档到游戏目录外，活跃 Saves 恢复到测试前的完整文件清单。未覆盖或删除任何原始存档。

同日后续的外网探测也已完成：在当前 Mac 对局 UI 中，两家公开测试接口的 HTTPS GET/POST 均返回空的 404，加密 WebSocket 未连接；电脑端对照全部成功。标准 XHR 二进制读取游戏已挂载资源成功，哈希与原件一致，但带 `LOAD_METADATA` 的存档列表仍只返回简介，没有完整配置或文件字节。详见[外网与存档接口实测](../../docs/research/civ7-https-live-test-2026-10-22.md)。该轮每次测试前另作完整备份，未退出对局、加载、保存或推进回合；游戏期间出现的后续存档更新也已完整备份，没有回滚当前进度。这不构成新版产品功能实机验收。

## 历史实现与范围

0.2.0 的“mod + 本地工具”路线已在 macOS / 游戏 1.5.0 实机验证：读档页复制设置后核对 834 个值，微调和直接开局两条分支都进入第 1 回合。更换领袖、文明、纪念物生效，种子保留。此结论仅针对旧辅助程序路线。

解析器仅接受已验证的 1.5.0 文件布局；整场游戏起始配置只接受最初时代的存档。跨时代快照不能冒充整场开局。截图只能填入看得到的字段，无法恢复完整纪念物、AI 身份、隐藏设置与依赖清单。

源存档只读。当前辅助链仍在内部创建唯一命名的原生配置供导入，不覆盖既有文件；用户界面中的“另存配置”功能已移除。新建对局可能轮换自动存档，不能以具名保存代替完整备份。
