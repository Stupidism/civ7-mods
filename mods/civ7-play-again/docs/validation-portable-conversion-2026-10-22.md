# 0.3.3-dev：配置转换内置化与原生路线静态核查

日期：2026-10-22，Asia/Shanghai。用户仍在游戏，要求不实机测试。本轮只改工作区、读取已安装静态资源与已有存档副本、运行离线测试。没有连接游戏进程/调试口、操作界面、修改安装目录、修改启动参数或读写当前 Saves。

## 实际完成

新增 `ui/save-configuration.js`，将原先 Node 转换器中的完整转换与核对数据生成移入可随 mod 打包的 JavaScript 核心：

- 输入存档字节，定位最初时代的 initial 配置，生成游戏原生 `.Civ7Cfg` 字节。
- 未改动的属性保留原字节，不通过逐个已知选项重建而丢弃 mod 属性。
- 仅调整已有验证依据的新局 PlayState，及调用方明确确认 `AffectsSavedGames=0` 的已安装界面 mod 版本。规则 mod 版本不能自动放宽。
- 原始配置与待加载配置各自保留独立的带类型快照；嵌套数组、64 位整数与原生值不共享引用。
- 转换核心不用 Node、Buffer、TextEncoder/TextDecoder、网络、文件系统、游戏全局对象或独立进程。
- 旧 `tools/export-config.mjs` 成为文件读写/哈希包装，`tools/expected-configuration.mjs` 复用相同核对核心；旧本地服务的转换结果也直接使用新核心生成的核对数据。

这使解析、转换、核对算法本身可以内置，**没有解决游戏 UI 取得所选存档字节以及让引擎读入转换结果的入口**。未新增一个要求玩家手动运行的替代方案，也未将尚未证实的接口接为默认流程。

## 原生路线核查结果

1. 原版热座读档进大厅的界面流程存在，但普通单人存档能否借此只恢复设置仍未验证。
2. 大厅正常退出、返回菜单、打开新建页都有重置配置的步骤。若此路线可行，必须退出前独立保存配置，待新建页初始化后恢复并重新核对；保存原对象引用不够。
3. 原版大厅具有自动开始倒计时。不能用隐藏/移除界面代替正常取消计时和退出流程。
4. 把普通存档标成 GAME_CONFIGURATION 的旧失败，可能发生在更早的文件路径检查：本机二进制静态调用链显示内容类型决定 `.Civ7Cfg`/`.Civ7Save` 扩展名。故不能用那个失败结果断言两种文件内容完全不可兼容；也不能因此推断已找到绕过方法。
5. 没有找到已验证的附带原生程序自动加载入口。把运行库复制到 mod 包内，仍不能解决自动启动和引擎通信。

详细来源、函数地址和生命周期证据见[研究记录](../../../docs/research/civ7-save-import-ecosystem-2026-10-21.md)以及 `work/civ7-save-research-20261021/native-lobby-analysis.md`。

## 尚未达到的验收条件

其他玩家只安装 mod，读档页点击后就得到完整新建设置——仍未打通，不能发布为可用功能。现阶段有实现依据的下一步，是验证一种能提供原始配置的原生入口；如果只有当前配置，则必须拒绝将其冒充原始开局。任何涉及真实 load/leave/start 的尝试，均须等用户恢复测试许可，并先按 AGENTS.md 完整备份和校验整个 Saves。
