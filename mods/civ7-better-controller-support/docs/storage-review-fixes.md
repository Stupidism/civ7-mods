# 0.10.2-dev 存储审查修复记录

## 审查发现的三个问题

1. **普通多键存储被过度拒绝。** 旧逻辑把“多于一行”本身当作歧义，没有区分后端能否按键准确读取。正常 keyed 后端中其他 Mod 的独立键不应导致本 Mod 拒绝读写。
2. **旧版升级丢失校准。** 0.3.0 使用独立的 `civ7-controller-bridge-v1` 键，新版只读取共享命名空间，缺少正常后端的加载和迁移路径。macOS key-blind 后端又无法可靠识别旧键，不能猜测记录归属。
3. **被拒绝的保存会在重建实例后生效。** 写入成功但读回校验失败时，旧实现只隔离当前实例，磁盘仍可能留下新值。修复将最终校验纳入回滚范围，同时覆盖首次保存、写后抛错与其他 Mod 交叉写入。

## 修复方式

- 用一次性缺失键探针区分本次后端的 keyed 读与 macOS key-blind 读，而不猜测操作系统。keyed 多键后端按准确 `modSettings` 键读写并保留所有外来独立键；key-blind 多键仍 fail-closed。
- 正常后端按准确旧键加载 0.3.0 校准；确认保存并校验成功后才迁移，取消不迁移。已有有效新版命名空间优先，格式错误的旧记录保留。
- key-blind 下的模糊旧数据不能自动识别。升级只允许离线审查备份：先用 `python3 tools/plan-controller-settings-migration.py --database /absolute/backup-LocalStorage.sqlite` 生成只读计划和源值 SHA-256，人工核对后用 `--apply-hash <reviewed-sha>` 在备份上事务执行。工具拒绝默认实时 LocalStorage，也拒绝无哈希的 `--apply`。
- 迁移按准确旧键和哈希合并 `civ7-map-tools-gamepad` 命名空间，保留 `modSettings` 其他字段和所有独立外来键，只删除仍匹配的旧手柄行。
- 首次创建失败时，只有确认整份共享文档仅含本次写入才删除整个键；若同文档出现外来根字段，则只移除本次命名空间并保留外来字段。写入在变更前被后端拒绝且存储仍为空时，直接报告原始错误，不误报回滚失败。
- key-blind 下从一行变为两行，即使首行字节没变，也不能证明新增键属于本 Mod，因此禁止据此删除任何键，明确报告回滚无法核实。若首行已变化且仍可匹配本次尝试及既有 BCS 命名空间，只恢复旧 BCS 值并保留其他字段与独立键。

## 边界与限制

- 这是 2026-11-09 记录的源码候选 **0.10.2-dev**：截至该日未发布、未安装、未进入实机或直播验证；本记录只覆盖当时的存储修复离线测试。后续若发生安装或验收，以新的带锁记录为准，本页不用于改写或否定新证据。
- 迁移工具永远不应指向真实游戏 LocalStorage。先完整备份并在备份副本上计划、审查和应用。
- 后端持续读写故障不能保证回滚成功。原始保存错误、读回错误与“回滚失败”分开报告；若回滚本身也被后端拒绝，不得宣称设置已恢复。
- 迁移保留独立外来键是数据安全要求，但不表示运行时兼容：若 key-blind 后端仍有多键，本 Mod 依旧拒绝自动选择目标并要求人工处理。未知首行旁新建共享记录又保存失败时，也可能保留两行以避免误删；此时新实例拒绝加载，而非启用被拒绝的校准。
- 持续后端读写失败不具备跨记录原子性：若恢复操作也被拒绝，错误会明确说明回滚失败，不能保证下一次进程仍读取旧值。
