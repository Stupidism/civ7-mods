# 0.9.1 手柄设置存储修复

## 方案与限制

实机验证否定了仅用原生用户选项的方案：当次进程可写可读，但完全重启后为 null。当前实现改用社区共用的 `modSettings` 唯一记录，在 `civ7-map-tools-gamepad` 命名空间保存 `{version: 1, controller: 五个布尔开关}`。

不再创建独立键、不清空存储、不全局代理第三方 API。更新时保留文档中其他所有字段。多键、格式错误、缺失已知配置或写入读回失败会报错；本次会话保留最后有效设置。冷启动没有有效设置时使用原生输入并对检测到的错误提示。首次空存储可创建共用记录；不能可靠识别旧记录时拒绝盲目覆盖。

此方案规避当前单键读取错误及第三方多键清空惯例，不修复引擎本身，也不能保证抵御第三方无条件清空全部设置。其他 Mod 若重新创建独立键，会显示迁移错误，不会静默采用那个对象。手柄输入映射算法未改变。

## 旧版迁移（候选版不能免迁移公开升级）

1. 获得授权及游戏锁，退出游戏，备份并核验最新 LocalStorage.sqlite。实测还必须完整存档备份与休息保护。
2. 对备份运行 `python3 tools/plan-controller-settings-migration.py --database /absolute/backup-LocalStorage.sqlite`。仅按准确 origin/key 读取旧手柄记录，输出原值 SHA-256、五个开关和目标命名空间。工具只读且拒绝默认实时数据库。
3. 游戏关闭时在事务中再次比对旧行 SHA-256，将目标命名空间合并到准确的 `modSettings` 行，保留该行所有其他字段；仅移除哈希匹配的旧手柄行。若已有新版配置、其他独立键或未知格式则停下调查，不能清空数据库。
4. 确认结果只剩一个共享记录。实际启动检查五个开关、确认/取消，然后彻底退出重启，检查值是否保留。再测试实际第三方共用设置写入和菜单/地图上下文。失败时使用备份恢复原记录，保持其他设置完整。
5. 记录迁移和恢复回执。实体手柄响应须单独验证，不能用模拟命名输入宣称通过。

144 项离线回归通过，包含单键/多键的 macOS key-blind 模拟、其他 Mod 命名空间保留、失败隔离、重建 store、确认/取消/默认及迁移只读检查。实机进度见 VALIDATION.md。
