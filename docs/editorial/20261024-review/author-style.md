## 写法

1. 先交代结果和背景，让没时间的读者先知道文章说什么。随后讲当时想做什么、哪一步出了问题、怎么调整。
2. 使用第一人称玩家视角。用具体回合、城市安排、单位操作解释问题；没有证据的经历只能明确写为假设，不能编造亲历战报或测试结果。
3. 保留适量玩家用语，如 T、档、读回去、节奏。技术名词只在读者需要找设置或存档时出现。
4. 自嘲落在具体失误上，点到为止；不堆梗、不造口头禅、不把每段写成段子。
5. 可以直接讲做错了、没有验完、还有优化空间。不要用宣传形容词替代实际结果。
6. 配图紧跟所讲的操作，图注简短，历史截图的版本边界仍需明确。不能把占位图、旧图当成当前实测证明。
7. Mod 专栏继续遵循用户要求：一个功能一章，每章从痛点讲到解决办法，再接实际效果图。结尾收回到这件小工具具体省了什么操作。
