# 功能任务的验收与发布跟踪

看板：[文明 VII — 版本与验收](https://github.com/users/Stupidism/projects/5)（所有者私有，关联 Stupidism/civ7-mods）。

打开[功能与修复任务](https://github.com/users/Stupidism/projects/5/views/1)，每行跟踪一个可独立验收和交付的功能或修复。用 `Mod` 自定义字段筛选归属。新增功能时选“功能任务”，原 Bug 直接更新已有记录。为同一 Mod 里验收或交付进度不同的功能分别建任务。

任务标题写具体行为，正文写验收标准、已观察到的结果、证据和构建。表中的“验收结论”回答这项行为是否完成验收，“实际发布版本”回答哪份公开发行包含它。已核实发布回执且可对应功能时填具体版本，已确认尚未交付填“未发布”，版本关系未知填“待核实”。版本号相同的开发补丁也需要独立的发布凭据。

2026-11-05 用户明确调整验收基线：已发布版本包含的功能直接标为“已验收”，注明“按用户确认的已发布基线承接”，不再因旧测试记录缺失列为待验收；不伪造新的实机或实体手柄记录。已知缺陷及发布后修改仍独立跟踪。

以有发布回执的发行包为基线，对比当前实际打包运行文件。用“发布范围”区分已发布基线、本次新增修改、历史方案和关联回归。新功能通过率仅统计“本次新增修改”任务，部分验收不计通过；已发布功能、被替代原型与无变化的旧功能回归不进入分母。新增或修复内容重点实机验收，受影响旧路径作针对性回归，未受影响功能沿用基线。

例如，微操大师0.6.3已交付攻击、归队、增援与普通快速转移，这些任务标为已验收。本次差异是商人等平民占格快速转移，作为独立新增任务验收。Bug的影响版本、修复构建及实际交付版本仍分别填写。

“待验收任务”按任务结论筛选；“Mod 资料”保留版本总览，“原综合验收清单”保留历史范围和证据。研发与测试进展优先更新功能任务。

用户已更正此前的笔误：所有验收记录统一使用中文，原英文要求已撤销。保留用于复现的原始字符串、截图语言、版本号、标识符和机器输出。

每次更新时：

1. 确认 Mod 和精确构建。同一个语义版本号可能对应不同文件。
2. 只有核实发布回执后才能更新公开版本。发布过程中保留上一个正式版本。
3. 记录实际测试、平台、输入方式和证据，区分离线检查、原生输入事件和实体设备测试。
4. 截图关联到实际测试构建。历史截图明确标注；没有截图时如实记录。
5. Bug 只填写已确认的影响构建和已验证的修复构建，保留未知边界。
6. 验收任务只有在所列检查完成，或范围经明确审阅调整后才关闭。新构建不得覆盖历史测试记录。
7. 「你的神图很好，现在是我的了」（`civ7-play-again`）开发已长期停滞，暂不通知、催办或唤醒其会话。保留 Bug 和验收缺口，不把停滞视为修复或通过；由用户明确恢复通知后再联系。

初始数据和远端操作回执位于 `work/mod-status-project/`。导入脚本只用于建立经审阅的快照，不是无人值守同步任务；旧英文初始化脚本不得覆盖当前中文记录。更新事实后须先审阅再修改远端。

未来实机测试继续遵守游戏锁、完整 Saves 备份和 Rest Guard 规则。看板条目本身不授予新的游戏控制或发布权限。
