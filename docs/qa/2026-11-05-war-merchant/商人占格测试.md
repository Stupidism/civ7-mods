# 商人占格快速转移：可重复实机脚本

三个入口：`prepare-merchant-fixture.mjs` 准备场景，`quick-transfer-civilian.mjs` 断言原生行为，`run-merchant-suite.mjs` 串联两条测试并截图。全部通过游戏调试接口运行，不使用 Computer Use。

## 运行前提

遵守仓库 AGENTS.md：取得当前游戏锁、设置本会话环境变量，完整压缩备份并逐文件核验 Saves，暂停 Rest Guard 全部限制。原版文件不得当作可丢弃样本。启动游戏仍须持锁。

固定样本为 `伊莎贝拉古典106.Civ7Save` 的隔离副本，游戏 seed `-526700269`、T106。副本命名为 `WarMerchant_20261105_merchant.Civ7Save`。若使用 `--load`，本轮加载前完整备份清单必须已包含这个副本，脚本会核对它的 SHA-256；不可拿旧轮次的恢复清单充数。私有存档不随脚本分发。

在仓库根目录，使用原生 ARM64 Node：

```sh
python3 scripts/game-lock.py run -- "$CIV7_NODE" scripts/with-game-activity.mjs debug -- \
  "$CIV7_NODE" mods/civ7-war-controls/tests/live/run-merchant-suite.mjs \
  --fixture /绝对路径/本轮加载前完整备份清单.json \
  --outdir /绝对路径/本轮输出目录 \
  --load WarMerchant_20261105_merchant.Civ7Save
```

`CIV7_NODE` 指向本机可运行的 Node 22+。`--load` 当前从已运行的游戏上下文重新载入，菜单首次加载另用仓库持锁加载脚本。不要并行启动两个游戏控制脚本。每次重载之前重新完成完整备份。

## 场景准备与断言

- 原生购买真实商人，金币不足时仅在测试准备阶段补足；通过实际单位列表识别新商人。
- 商人沿原生移动路线到 `(17,22)`；准备阶段可恢复商人移动力、取消旧路线并续走。正式测试期间不补移动力、不替换原生许可或完成事件。
- 指挥官 `262146` 位于 `(17,23)`。鼠标场景使用 `589831`，手柄场景使用 `2686999`，都先检查源位置、移动力、未登船以及无优先攻击目标。
- 正式动作必须恰好发出一次 ADD 和一次 REMOVE，收到真实加入、移出事件，最终位置准确、脱离军队、移动力仅减少 1；指挥官位置和移动力不变，商人仍在原格，没有 MOVE_TO 等操作请求。
- 鼠标路径调用原生地图选择；手柄路径明确建立地图焦点，确认光标目标后经 ContextManager 注入按下/松开。它不验证实体鼠标/手柄硬件，也不验证选中单位后的自动焦点转移。
- 两条路径之间，仅把第一名测试单位通过原生 ADD 收回，腾出目标格；第二名单位使用自己的原始移动力。

输出 `scene.json`、`mouse.json`、`controller.json`、`suite.json` 和两张中文命名原始游戏截图。发生失败时返回非零退出码，保留失败步骤，不将场景缺失标为功能通过。
